A fix for a packaging defect that stopped the Windows desktop application from
starting at all.

## If you installed 0.1.0 on Windows

Download and install this release. The 0.1.0 installer completed successfully
and then the application never opened a window — it could not, for the reason
below. Automatic updates cannot rescue it either, because the failure happened
before the updater was reached, so a manual download is the only way forward.

Your documents are unaffected. They live in SQLite under your user data
directory and were never touched by the fault.

## What was wrong

The desktop application stores documents through Node's built-in `node:sqlite`.
That module is still marked experimental, and so it is absent from the
`builtinModules` list that the main-process bundler used to decide what to leave
external. It was therefore treated as an ordinary dependency, could not be
resolved, and was replaced with an empty module — with a build warning rather
than a build failure.

The packaged application then tried to open its database against nothing at all.
That happens during startup, before the first window is created, and the
resulting error was discarded rather than reported: no window, no message, no
log. The application simply exited.

Two changes fix it. `node:sqlite` is now declared external explicitly instead of
being inferred, and an import the bundler cannot resolve now fails the build
outright. The second matters more than the first: it is what stops this shape of
defect from ever again passing as a successful build.

## Also in this release

- The desktop release pipeline now bakes the target environment and update
  channel into the package, verifies the Squirrel update manifest's SHA1, size
  and version against the payload it names, and refuses to publish an
  incomplete or stale set of artifacts.
- A guide to running the mobile application under Android Studio.

## Known limitations

Unchanged from 0.1.0: the installers are unsigned, so Windows SmartScreen and
macOS Gatekeeper warn on first launch — verify your download against
`SHA256SUMS.txt`. macOS auto-update needs a signed build. Windows ARM64 is
installer-only. Mobile applications are not published yet, and cloud sync is not
enabled.
