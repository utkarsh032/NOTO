## Highlights

- **Accounts work.** Sign in with an email and password and Noto is signed in — a real profile on the Home and Account screens, and this browser listed as a device. Everything before this read a fixture.
- **Sign-up, protected by Cloudflare Turnstile.** Creating an account now goes through a bot check that is verified server-side, where the secret that makes a token mean anything never reaches a browser.
- **Signed out is still the whole application.** Nothing here is a gate. Noto opens, writes and searches with no account, and a build with no Supabase credentials behaves exactly as it did before.

## Improvements

- The cloud loads only when it is needed. `@supabase/supabase-js` moved out of the entry bundle behind a dynamic import, so a visitor who has never signed in no longer downloads 164 kB to be told they are signed out.
- Password rules are stated once, in `@noto/config`. The sign-up form and the service previously kept their own minimum and disagreed by four characters, which the person signing up discovered on submit.
- Validation failures arrive on the field that caused them. The server has always sent per-field detail; nothing was displaying it.

## Bug fixes

- Sign-in and sign-up failed from a browser with "Could not reach the server". The Edge Functions' CORS preflight did not name the `apikey` header that every Supabase call sends.
- Edge Functions can now import the workspace packages they were always meant to share. Deno could not resolve the extensionless relative imports the bundler accepted, so no function using `@noto/backend` had ever deployed.

## A note on password strength

The Have I Been Pwned lookup, the common-sequence list and the email-substring
rule have been removed from sign-up, and the minimum length is six characters.
A password already present in a public breach corpus is now accepted. Turnstile
and the per-IP rate limit are what guard the endpoint.
